第一轮结果独立保留：F vs B 为 +1.7 个百分点，95% 区间 [−2.0, +5.0]。第二轮是看过第一轮结果后的新研究，不追溯修改原预注册。目标是获得清楚的证据，不保证正向结果。

沿用 PlaceSphere、RGB + proprio、N=100、原 baseline final.pt、horizon=200、冻结视觉编码器、动作归一化与去噪配置。探索使用 s1；确认使用 s1–s3。第二轮先研究固定引导，不扩大 adaptive 搜索。

## 阶段 1：配对失败诊断

从第一轮 JSON 按 (checkpoint, episode seed) 提取 F/B 不一致回合：13 个 B 失败、F 成功；8 个 B 成功、F 失败。已有视频优先；缺失时用相同 checkpoint、推理 seed、num_envs 和 horizon 重放，先核对结果是否复现。

诊断问题：引导是否帮助最后放置，却破坏前面已经正确的动作？模型是否只是对同一种失败重复学习？这些是待检查假设，不能由 success_once 或噪声余弦直接得出。

交付：21 对回合对照表、代表视频、共同失败抽样表。旧 test 仅用于探索解释，不再用于第二轮选参数或正式确认。

## 阶段 2：单 checkpoint 小网格探索

使用 s1，lr=1e-5、batch=64、编码器冻结，每次都从 baseline 开始。仅改变两项：

| 失败轨迹 K | 训练 checkpoint |
| --- | --- |
| 150 | 5000、10000 steps |
| 300 | 5000、10000 steps |

每个 K 训练到 10000 steps 并保存 5000-step checkpoint，共两次训练、四个候选。相同步数比较用于固定计算预算；150/5000 与 300/10000 另作近似相同数据遍历次数的参考，不能混称纯数据量对照。第一轮已有的 150/5000 模型若 provenance 完全一致可复用。

离线评估使用未参与训练的新 holdout，记录 gap_fail、gap_succ、margin；不同 K 的模型在同一 holdout 上比较。失败模型 loss 更低不作为闭环有效的结论。

固定引导 alpha 网格为 {0.25, 0.5, 1.0}；每候选在相同的 48 个新筛选 seed 上评估，B 同 seed 评估一次。记录成功数、配对得失、分 timestep 的噪声改动、实际动作块差异、截断比例及延迟。B 应记录同定义的 x0 截断比例。

先选每个 K 的最佳 steps/alpha，再在相同 128 个独立验证 seed 上评估这两个锁定候选和 B。筛选成功数相差不超过 2 回合时，依次偏好较小 alpha、较少训练步数。验证结果只决定继续或停止，不再反复调参。

### 继续条件（探索决策规则，不是显著性标准）

进入正式确认需同时满足：

- K=300 的锁定候选在独立验证上相对 B 至少 +5 个百分点（128 回合需净增至少 7 次成功）；
- K=300 成功数高于 K=150 的锁定候选；
- 离线门控通过，配对明细与代表视频未暴露明显的评估或数据错误。

这些条件仅是有限预算下的推进标准。单 checkpoint 验证通过不能宣布多种子有效。失败则停止数据量扩充，不自动升级到 K=600 或持续延长训练。

交付：四候选筛选表、两候选独立验证表、继续/停止决定及证据。

## 阶段 3：多 checkpoint 独立确认（阶段 2 通过才执行）

在 s1–s3 上使用选定 K=300、统一 lr/steps/alpha。成功-rollout 模型也使用 300 条成功轨迹，并采用相同训练配置，以检验收益是否特异于失败信息。现有原始采集每个 seed 仅记录 150 条成功，需要继续采集并记录来源；现有不足 300 的失败也需补齐。按 seed 顺序选择，不按失败难度挑选。

固定四组：B（基线）、F（失败负向引导）、C1（成功负向引导）、C2（成功自模仿）。C1 在独立 tuning 集按预先写定网格和规则选择 alpha；其他第二轮已选参数在确认 test 前锁定。

若要声称“增加失败数量带来提升”，需额外评估三个 checkpoint 的 K=150 参考组，并匹配所比较的 steps/alpha；只有 F300 vs B 显著不足以证明数据量作用。为控制预算，默认第二轮正式主张限于改进设置的有效性，数据量趋势作为探索结果。

test 前提交第二轮协议、锁定文件、模型 hash、seed 清单、主假设及分析脚本。每组每 checkpoint 300 个新 test 回合，四组共 3600 回合。各组使用相同环境 seed、推理 seed、num_envs 和 horizon。

统计沿用配对设计与两层 bootstrap（先 checkpoint，再回合），10000 次，报告95%区间、各 checkpoint 成功数和配对得失。主比较 F vs B；归因比较 F vs C1；C2 作为自模仿对照。仅三个训练 checkpoint 是泛化范围的限制，增加回合不能替代增加训练 seed。

结论规则：

- F vs B 与 F vs C1 的区间都严格大于零：支持当前设置下失败引导有效且优于该成功轨迹对照。
- 只有 F vs B 支持正向差异：支持引导收益，失败信息的独特贡献未获支持。
- F vs B 跨零：报告估计效应与区间，不声称有效，也不把它等同于证明无效。
- 若预先将 +5 个百分点定义为具有实用价值的增益，且其区间上界低于 +5：可表述当前设置不支持这种规模的收益。不能外推为所有任务或方法变体无效。

## 预算、顺序与停止条件

- 探索预算上限建议 8 GPU-h；按第一轮 rollout 0.105 GPU-h/100回合及引导开销约2倍粗估，阶段2最多576个guided筛选回合、256个guided验证回合，另有176个baseline回合，闭环部分约1.9 GPU-h。这是规划估算，需以首批实测重估，另计训练、holdout、启动与视频成本。
- 正式确认追加上限建议16 GPU-h；3600回合中1800为guided（F/C1）、1800为单模型（B/C2），粗估评估约5.7 GPU-h。另计补采成功数据、模型训练和C1 tuning，开跑前做完整预算核算。总建议上限24 GPU-h，不代表已获配额或已提交作业。
- 依次执行：原始产物检查 → 配对诊断 → s1小网格 → 独立验证 → 决定是否多seed确认。结果未出现时不提前启动下一阶段。
- 停止条件：数据/复现错误未解决；离线gate不通过；独立验证未达到推进标准；预算耗尽。修复流程错误可重跑受影响部分，但不能以不满意结果为理由无限追加候选。
