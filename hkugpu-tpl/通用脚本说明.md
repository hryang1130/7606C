# ManiSkill 训练模板使用说明

`train_template` 把环境、训练循环、GPU 加速、评测、视频和结果报告集中管理。组员只需复制 `tasks/_template`，在新任务目录填写任务配置与适配代码；共享引擎不应出现某个 task 的特例。

最简命令调用顺序和所有可替换参数见：[通用命令调用说明](README.md)。文档中的 `<task_id>`、`<model_name>` 等占位符必须替换为实际任务或模型名称。

## 目录分工

- `setup_linux_uv.sh`、`pyproject.toml`、`uv.lock`：Linux + NVIDIA GPU 的独立 uv 环境。无需 sudo、apt、Conda。
- `common/`：统一训练、检查点、评测、视频调度、可视化报告和插件加载逻辑。通常不修改。
- `tasks/_template/`：新任务的接口骨架。所有 `TODO` / `FILL_ME` 都是组员需要填写的位置。
- `tasks/task_06/`：PlugCharger-v1 的完整示例，包含数据、MLP/U-Net/Transformer、DP 策略和 ManiSkill 环境适配。
- `run.py`：共同命令入口。
- `run_experiments.sh`：逐模型、逐随机种子训练和评测，结束后生成报告。
- `runs/`、`reports/`、`data/`：运行时产物，已在 `.gitignore` 排除。

## 新建任务

从模板根目录复制骨架并取一个 Python 标识符作为目录名，例如：

```bash
cp -a tasks/_template tasks/task_07
```

复制后目录名就是 Python 插件名，现有 `__init__.py` 的相对导入会自动指向新目录中的模块。请依次完成：

1. `config.py`：填写 ManiSkill task id、obs/action 维度、控制模式、时域、`data_dir`/数据路径、可比较模型名单和评测配置。`default_models` 的每一项必须对应 `models.MODEL_REGISTRY`。
2. `data.py`：实现轨迹读取、归一化/预处理、按 episode 拆分 train/validation、时序窗口构造和末端 padding。`load_datasets(path, seed, validation_fraction, limit, config)` 必须返回两个 Dataset；每个 Dataset 的 `__getitem__` 返回 `(observations, actions)` 两个 Tensor，形状分别为 `[obs_horizon, obs_dim]` 和 `[prediction_horizon, action_dim]`。禁止把同一条轨迹的窗口随机拆到训练集和验证集两侧。
3. `models.py`：在这里编写不同网络结构并登记在 `MODEL_REGISTRY`；网络接收带噪动作、扩散步和观测条件，输出与动作序列同形状的预测。
4. `policy.py`：实现 `build_policy(model_name, obs_dim, action_dim, config)`。返回的 `nn.Module` 必须在 `forward(observations, actions)` 返回一个标量训练损失；另实现 `predict_actions(policy, observations, inference_steps, config)`，返回 `[batch, prediction_horizon, action_dim]`。如可获益，可实现 `compile_for_inference(policy)`。
5. `training.py`：实现 `compute_loss(policy, observations, actions, config)`。模板默认直接调用 `policy(...)`；有额外正则项、辅助损失或算法训练步骤时，在此组合。共享训练器负责反传、梯度裁剪、优化器、EMA、学习率计划和日志。
6. `environment.py`：实现 `make_eval_env`、`make_video_env`、`observation_tensor`、`video_observation`、`select_action_chunk`、`success_mask`、`video_action`。评测环境应返回 ManiSkill vector API；视频环境需使用 `render_mode="rgb_array"` 和 `RecordEpisode`。处理好你的环境终止条件和成功信号。
7. 如官方数据需要下载/转换，在 `prepare_data.py` 提供 `prepare(data_dir, conversion_workers)`；然后从通用 `prepare-data` 命令调用。

**动作时间对齐必须由任务适配器明确处理。** `select_action_chunk` 决定预测序列中的哪一段实际执行；它要与数据构造的窗口对齐方式一致。连续动作与离散动作的边界、action space 缩放也由任务代码负责。

## 安装与检查

在 Linux GPU 节点上从 `train_template` 目录运行：

```bash
bash setup_linux_uv.sh
uv run python run.py models --task <task_id>
uv run python run.py smoke --task <task_id>
```

环境固定 Python 3.11、PyTorch CUDA 13.0 wheel 与 ManiSkill 3.0.1。CUDA toolkit 不需系统安装，但远程节点驱动、GPU 映射和 Vulkan/渲染运行依赖必须可用。smoke 会检查每种模型的 loss/反传/采样、仿真 reset/step 和 MP4 写入；新任务目录所有 `TODO` 填完后才应通过。

## 任务命令

```bash
uv run python run.py prepare-data --task <task_id> --conversion-workers <conversion_workers>
uv run python run.py train --task <task_id> --model <model_name> --seed <seed>
uv run python run.py evaluate --task <task_id> --checkpoint runs/<task_id>/<model_name>/seed_<seed>/best.pt
uv run python run.py video --task <task_id> --checkpoint runs/<task_id>/<model_name>/seed_<seed>/best.pt
uv run python run.py report --task <task_id>
```

训练和评测的默认参数由 `tasks/<task_id>/config.py` 提供；模型名必须来自该任务的 `default_models`。输出路径中的任务、模型和 seed 都使用命令中实际传入的值。要缩短本地验证，可传 `--steps 2 --batch-size 16 --no-compile --amp off`。

## 多模型实验和报告

```bash
TASK=<task_id> bash run_experiments.sh
```

默认按 config 中的模型名单和种子 `1 2 3` 顺序运行，避免多个任务同时争抢单卡。可通过环境变量覆盖：

```bash
TASK=<task_id> MODELS="<model_name_a> <model_name_b>" SEEDS="<seed_a> <seed_b>" STEPS=1000 BATCH_SIZE=128 EVAL_EPISODES=16 bash run_experiments.sh
```

每次 run 保存 `best.pt`、`latest.pt`、`metrics.jsonl` 和 `run_config.json`。评测结果是固定环境 seed 的 per-episode CSV/JSON；`report` 和 `compare` 会产出 `reports/<task>/report.html`、`training_curves.png`、`model_comparison.png`、CSV 和 JSON。HTML 保留完整报告，PNG 可直接单独查看。最终报告应注明模型训练种子、环境测试 seed 区间、episode 数、采样步数、仿真 backend 和训练配置；不要用调参时反复查看的测试 seeds 作为唯一最终结果。

## GPU 优化策略

共享训练器在 CUDA 上启用 TF32、cuDNN autotuning、fused AdamW、BF16（硬件支持时）、固定 shape batch 的 `torch.compile(mode="reduce-overhead")`、GPU 常驻 window 数据、EMA 权重及 warmup+cosine LR。推理 compilation 由任务插件可选启用；环境评测由插件设置 PhysX GPU 向量环境数量。渲染视频与控制模式转换走 CPU PhysX，是为了支持 ManiSkill 的渲染/转换接口，并非放弃训练或并行评测加速。编译故障排查可用 `--no-compile`，数值对照可用 `--amp off`。
