## 1. 摘要

在 ManiSkill 3 的 **StackCube-v1** 任务上，用 **Diffusion Policy + RGB UNet** 做 imitation learning，固定其它条件，只改变演示轨迹数 **N ∈ {25, 50, 100, 200, 400}**，共跑 **21 次训练**（N=25/50 各 3 个种子，N=100/200/400 各 5 个种子），每个 checkpoint 用**同一组测试种子（10000–10099，100 回合）**评测 `success_once`。

> **v2 更新（2026-10-05）**：dataloader 优化（`data.preload` 默认开启，实测吞吐 2.34×）把单 run 训练从 4.5 h 压到 2.2 h，配额因此腾出余量，**N=400 档已实测**并完成评测。本报告据此重写了 §1、§3、§4.1、§4.2 与 §5.1：原来"N=400 外推 0.925"的段落改为**外推与实测的对照**，并对当初的四个候选模型逐一打分。

主要结论：

| 结论 | 证据 |
|---|---|
| 成功率随数据量**单调上升**，每档提升统计显著 | 相邻档位两层 bootstrap 差值 +0.106 ~ +0.273，95% CI 全部不含 0 |
| **N=400 实测 = 0.832 ± 0.019**（416/500） | 5 个种子全落在 0.81–0.86，补齐了 v1 的空档 |
| **仍未饱和，但已越过 log-linear 段** | 每翻倍增益**首次回落**：+0.287 → +0.250 → **+0.172**；局部 α 0.69 → **0.33** |
| 相对增益持续衰减 +640% → +232% → +61% → **+26%** | 天花板压缩已明显，但增益仍显著不为 0 |
| **v1 的四个外推模型全部高估 N=400** | logistic 预测 0.926（实测 0.832，偏差 +0.094）；最朴素的"增益衰减法"反而最接近（+0.046） |
| val_loss 幂律仍成立，且**指数略微变陡** | 含 N=400 重拟合 `val_loss ∝ N^(−0.828)`，R² = 0.9957 |
| 训练算力对 N **几乎不敏感** | N≤200 四档 4.48–4.64 h（+4%）；N=400 在优化后的 dataloader 上 2.23 h/run |
| 数据是**嵌套子集**，排除了"换一批数据"的混淆 | N=25 的 25 个演示种子在每一档中都存在 |
| 已排除「数据量 vs 梯度步数」混淆 | 五档 `train.total_iters` 同为 **100000**，唯一变量是 `num_demos` |
| **是泛化的 scaling，不是拟合的 scaling** | 各 N 的 train loss 都压到 1e-4~1e-3（近零），val_loss 却从 0.186 降到 0.018 |
| val_loss 是**高信噪比**的替代指标 | 种子间 CV 1–2.4%（N=400 为 5.8%），远优于 success_once 的 2.3–69% |
| 按 final-plan §6.5，**N_B = 100 冻结**给队友做 B0 参照 | UNet@100 = 0.410 ≥ 0.10 |

## 2. 实验设置

### 2.1 任务与数据

| 项目 | 值 |
|---|---|
| 仿真环境 | ManiSkill 3，**StackCube-v1**（把红立方体堆到绿立方体上） |
| 观测模态 | RGB 图像（run 目录名前缀 `stackcube_rgb_unet`） |
| 演示数据来源 | 【待补：脚本生成 / 强化学习策略回放 / 人类遥操作；单条轨迹平均长度】 |
| 演示轨迹数 N | 25 / 50 / 100 / 200（正式档，`configs/experiments/data_size.toml`）**+ 400（可选档，`configs/experiments/data_size_optional400.toml`）**，均由 `data.num_demos` 驱动 |
| **子集结构** | **嵌套（nested）**：N=25 的 25 个演示种子完整包含在 N=50/100/200/400 中。即每一档 = 上一档 + 新增演示，而非重新采样 |
| **N=400 的特殊性** | 训练池总共**只有 400 条**（演示种子 < 4000），所以 **N=400 = 全集**，是本数据池的天花板，再往上必须重新生成演示数据。toml 里也明确写着它"不属于正式 grid" |

> **嵌套设计为什么重要**：它保证"多出来的性能"只可能来自**新增的演示**，而不是来自换了一批数据带来的分布差异。这比独立重采样的设计更干净，也让我们对 §3.5 的边际收益分析更有信心。代价是：N=25 / 50 档实际上观测到的是"数据极度稀缺"的情形，而不是"另一种采样下的 25 条"。

种子分配同样由 toml 固定（`[replicates]`），与 §2.2 一致。

### 2.3 评测协议（重要，决定了结果可比性）

| 项目 | 值 |
|---|---|
| 主指标 | `success_once`（回合内任意时刻成功即算成功） |
| 测试种子 | 10000–10099，**每个 checkpoint 都用同一组** |
| 回合数 | 100 |
| 并行环境数 | NUM_ENVS = 4 |
| 结果文件 | `$RUN_ROOT/<run>/eval/test_final.json` |

> **为什么要用同一组测试种子**：这样不同 N 之间的比较是**配对**的，消除了"回合难度"这一共同方差。实测支持这一点：种子间 SD ≈ 0.029，而若回合独立重抽，二项噪声应为 SD ≈ 0.049。配对设计让功效大约翻倍，这正是我们用两层 bootstrap 的前提。

### 2.4 算力消耗

| N | 单 run 墙钟（seed 1，`summary.json.wall_time_s_this_invocation`） | 峰值显存 |
|---|---|---|
| 25 | 16118.9 s = **4.48 h** | 3677.8 MB |
| 50 | 16512.8 s = **4.59 h** | 3677.8 MB |
| 100 | 16119.5 s = **4.48 h** | 3677.8 MB |
| 200 | 16714.9 s = **4.64 h** | 3677.8 MB |
| **400** | 8039 s = **2.23 h**（⚠️ 不同代码版本，见下） | 【待补】 |

已知四档（N≤200）的显存完全一致 → batch size 未随 N 变化（N=400 的峰值显存【待补】）。

N 从 25 涨到 200 **只多花 4% 的时间**（数据加载开销远小于反向传播开销）。这是个值得写进报告的观察：**在这套配置下，"更多数据"的训练成本几乎是免费的，成本在于获取演示数据本身。**

> ⚠️ **N=400 的墙钟不可与上面四档直接比较。** v2 之前上游优化了 dataloader（`data.preload` 默认 `true`：训练前把选中演示的 RGB 一次性解码进内存，约 15 MB/demo，N=400 ≈ 6 GB），官方实测吞吐 **2.34×**（job 135722，GPU 利用率 51% → 88%）。N=400 的五档实测分别为 **8039 / 8036 / 8052 / 8102 / 7667 s**，平均 **7979 s = 2.22 h**。若按 N=200 的旧速度折算，同样 100000 iters 本应需要 ~4.7 h → 实际提速约 **2.1×**（略低于 2.34×，因为 N=400 的数据量是 N=200 的两倍，preload 与采样开销更大）。该优化**只改读取路径、不改样本**（`data.preload` 被 Gate B 明确排除在 `control_hash` 之外），因此不影响任何 scaling 结论。

N=400 × 5 seeds 训练共耗约 **665 GPU-min**，评测再耗约 50–100 GPU-min。

## 3. 结果

### 3.1 各 N 档汇总

| N | 种子数 | 均值 | 种子间 SD | 均值标准误 SEM | min | max | 汇总成功数 |
|---|---|---|---|---|---|---|---|
| 25 | 3 | 0.017 | 0.012 | 0.007 | 0.010 | 0.030 | 5 / 300 |
| 50 | 3 | 0.123 | 0.025 | 0.015 | 0.100 | 0.150 | 37 / 300 |
| 100 | 5 | **0.410** | 0.029 | 0.013 | 0.370 | 0.450 | 205 / 500 |
| 200 | 5 | **0.660** | 0.031 | 0.014 | 0.620 | 0.690 | 330 / 500 |
| 400 | 5 | **0.832** | 0.019 | 0.009 | 0.810 | 0.860 | **416 / 500** |

**完整曲线：1.7% → 12.3% → 41.0% → 66.0% → 83.2%。**

### 3.2 逐 run 详情（成功数 / 100，95% Wilson 区间）

| N | seed 1 | seed 2 | seed 3 | seed 4 | seed 5 |
|---|---|---|---|---|---|
| 25 | 0.030 [0.010, 0.085] | 0.010 [0.002, 0.054] | 0.010 [0.002, 0.054] | — | — |
| 50 | 0.120 [0.070, 0.198] | 0.100 [0.055, 0.174] | 0.150 [0.093, 0.233] | — | — |
| 100 | 0.400 [0.309, 0.498] | 0.370 [0.282, 0.468] | 0.420 [0.328, 0.518] | 0.450 [0.356, 0.548] | 0.410 [0.319, 0.508] |
| 200 | 0.660 [0.563, 0.745] | 0.640 [0.542, 0.727] | 0.690 [0.594, 0.772] | 0.620 [0.522, 0.709] | 0.690 [0.594, 0.772] |
| 400 | 0.810 [0.722, 0.875] | 0.830 [0.745, 0.891] | 0.840 [0.756, 0.899] | 0.860 [0.779, 0.915] | 0.820 [0.733, 0.883] |

注意三件事：

1. **相邻档位的 Wilson 区间已经开始重叠**：例如 N=200 seed 3 的 0.690 [0.594, 0.772] 与 N=400 seed 1 的 0.810 [0.722, 0.875] 在 0.72–0.77 一带仍有交叠。单个 run 的 100 回合精度只有 ±0.08 左右，**不能拿单个 run 比较，必须用种子均值 + 配对 bootstrap**。
2. **种子间 SD 在各档都稳定在 0.019–0.031**，绝对离散度不随 N 放大（反而随成功率升高被天花板略微压缩），说明训练过程本身是稳定的，趋势不是被某几个坏种子拉出来的。
3. **N=400 的 CV 降到 2.3%**（N=25 时是 69%），即高成功率区间内种子噪声最小 —— 这也意味着在大 N 侧，**用 5 个种子已经足以分辨比 ±0.05 更大的差异**。

### 3.3 相邻档位比较（两层 bootstrap，10000 次）

先重抽训练种子，再重抽测试回合；只在两档共有的种子上配对。

| 比较 | 均值差 | 95% CI | 配对种子 | 结论 |
|---|---|---|---|---|
| 25 → 50 | +0.106 | [+0.060, +0.157] | 1, 2, 3 | 显著 |
| 50 → 100 | +0.273 | [+0.207, +0.340] | 1, 2, 3 | 显著 |
| 100 → 200 | +0.250 | [+0.182, +0.318] | 1, 2, 3, 4, 5 | 显著 |
| **200 → 400** | **+0.172** | **[+0.108, +0.236]** | 1, 2, 3, 4, 5 | **显著（尚未饱和）** |

**N=200 → N=400 是这条曲线上第一个"增益变小"的 doubling，但它仍然显著不为 0**，所以说"N=400 尚未饱和"是有统计支持的结论，不是外推。

### 3.5 独立佐证：held-out 演示上的验证损失（不依赖回合采样）

每个 run 的 `metrics.jsonl` 末行给出了 100k step 处的 train/val loss（验证集固定为 `val_num_demos = 50`，不随 N 变化）。这条证据**与评测回合的随机性完全无关**，是比成功率更"干净"的第二条曲线：

全部 **21 个 run** 均已跑满 `step = 100000`，末行 `lr = 0.0`。

| N | 种子数 | val_loss 均值 ± SD | 变异系数 CV | train_loss 均值 | val/train |
|---|---|---|---|---|---|
| 25 | 3 | 0.18580 ± 0.00212 | 1.1% | 0.000246 | 757× |
| 50 | 3 | 0.10583 ± 0.00244 | 2.3% | 0.000838 | 126× |
| 100 | 5 | 0.066320 ± 0.000954 | 1.4% | 0.000359 ± 0.000123 | 185× |
| 200 | 5 | 0.035649 ± 0.000840 | 2.4% | 0.000624 ± 0.000483 | 57× |
| **400** | 5 | **0.018153 ± 0.001051** | **5.8%** | **0.001029 ± 0.000610** | **18×** |

> 全部 21 个 run 的完整逐 run 数据见附录 B 的提取命令；上表为按 N 汇总。**train loss 在五档都处在同一个量级（1e-4 ~ 1e-3）**，而 val loss 跨了整整一个数量级（0.186 → 0.018）—— 这个对比是 §5.4 的核心证据。val/train 倍数从 757× 单调降到 18×，即"相对训练集的泛化缺口"随数据量持续收窄，**但即使在 N=400 仍未闭合**。

**① val_loss 幂律在加入 N=400 后依然成立，指数略微变陡：`val_loss ∝ N^(−0.828)`，R² = 0.9957**（v1 由四点拟合得到 `−0.782` / R² = 0.9973）。每次翻倍下降约 **43.7%**。五个点仍近似落在一条直线上**且没有出现平台** —— 这是"尚未饱和"最干净的一条独立证据，因为 val_loss 不受 success 的 1.0 天花板压缩。

> 值得注意：N=400 的种子间 CV 升到 **5.8%**（其它档 1.1–2.4%），主要是 seed 5 偏高（0.019944，比其余 4 个高约 13%）拉开的。但 seed 5 的成功率是 0.820，处于该档中游 —— 又一次印证了 §3.5 ③ 的结论：**同一档内部，val_loss 预测不了哪个种子更好**。

**② val_loss 的信噪比远高于成功率。** 同一个 N 内，val_loss 的种子间变异系数只有 **1.1%–2.4%**，而 `success_once` 的 CV 是 **4.7%–69%**（N=25 档甚至高达 69%）：

| N | val_loss CV | success_once CV |
|---|---|---|
| 25 | 1.1% | 69.3% |
| 50 | 2.3% | 20.4% |
| 100 | 1.4% | 7.1% |
| 200 | 2.4% | 4.7% |
| 400 | 5.8% | 2.3% |

**这是本文最实用的方法学结论**：用 val_loss 做 scaling 分析，**3 个种子就足以分辨相邻档位**；而用 100 回合的成功率则需要 5 个种子 + 配对 bootstrap 才能达到同等功效。若后续还要做数据规模实验（或队友的轨道 B 需要比较 backbone），**优先用 held-out 演示上的 val_loss 作主指标**，把闭环 rollout 留给最终确认 —— 同样的算力，统计功效高一个数量级。

**③ 两个指标口径一致（且 N=400 加强了这一结论）。** 全部 **21 个 run** 的 val_loss 与 success_once 呈强单调负相关（Spearman ρ = **−0.964**，p = **2.1×10⁻¹²**），比 v1 只用 16 个 run 时更强（ρ = −0.937，p = 9.3×10⁻⁸），说明 loss 的改善确实对应行为层面的改善，两者不是各说各话。

> 顺带一个有用的对照：**train_loss 与成功率的相关性不显著**（跨全部 21 run ρ = **+0.384**，p = 0.086）。这正是应有的样子 —— train loss 在所有 N 上都已被压到同一个噪声量级，它不携带"哪个策略更好"的信息；真正携带数据规模信号的是 val_loss。**要做模型选择，只有 val_loss 有用，train_loss 没用。**

⚠️ **但相关性只存在于跨 N 层面，不存在于同 N 的种子之间**：

| N | 档内 Spearman ρ（val_loss vs success） | p |
|---|---|---|
| 25 | +0.866 | 0.333 |
| 50 | −1.000 | n=3，无意义（三点完全秩相关的确切 p = 1/3） |
| 100 | −0.800 | 0.104 |
| 200 | +0.667 | 0.219 |
| **400** | **−0.400** | **0.505** |

**没有任何一档显著**（N=50 的 −1.00 是 3 点样本的秩完美排列，不构成证据）。N=400 这一档尤其直观：**val_loss 最低的 seed 4（0.017472）成功率最高（0.860），看着"支持"正相关；但 val_loss 最高的 seed 5（0.019944）成功率 0.820 反而高于 seed 1（0.017491 → 0.810）和 seed 2（0.018251 → 0.830）中的一个** —— 整体排序对不上，ρ 只有 −0.40。即 **val_loss 能预测「数据更多 → 更好」，但预测不了「同一档里哪个种子更好」** —— 种子级的成功率波动完全淹没了 loss 的差异。这一点必须写清楚，否则会被误读成「可以用 val_loss 挑 checkpoint」。

**④ 更关键的是 train loss 这一列**：五档（N=25…400）的 train loss 全部压到同一个量级 1e-4 ~ 1e-3（N=400 均值 0.001029 ± 0.000610，甚至略高于 N=100），**每个模型都把它的训练演示拟合到了近乎无损**，而 val loss 高出 18–757 倍。这直接排除了竞争解释 —— 「N 小的模型之所以差，是因为没训够」不成立，它们同样把训练数据背下来了，只是泛化不出去。因此本文的 scaling 效应**本质上是泛化能力的 scaling，而不是拟合能力的 scaling**（详见 §5.4）。

### 3.6 边际收益分析

| 区间 | 绝对增益 | 相对增益 | 局部幂律指数 α | 折算每 +100 条演示的收益 |
|---|---|---|---|---|
| 25 → 50 | +0.106 | +640% | 2.89 | +0.427 |
| 50 → 100 | +0.287 | +232% | 1.73 | **+0.573（效率最高）** |
| 100 → 200 | +0.250 | +61% | 0.69 | +0.250 |
| **200 → 400** | **+0.172** | **+26%** | **0.33** | **+0.086** |

**最有意思的一点：单位数据的收益在 50 → 100 这段最高（每 100 条演示换 +0.573），而不是在最开始。** 典型解释是「冷启动门槛」——N=25 时策略连基本的抓取都学不稳（1.7%），大部分数据被用来跨越"从 0 到有用"的阈值；一旦越过去，数据才开始线性地兑换性能。这跟很多 BC 论文里观察到的"数据量小于某个临界值时几乎没有学习信号"是一致的。

**v2 补上的关键一格：200 → 400 是这条曲线上第一个明确走弱的 doubling。** 每翻倍增益序列为 +0.107 → +0.287 → +0.250 → **+0.172**，第一次出现下降；每 +100 条演示的收益从峰值 +0.573 掉到 **+0.086**（只剩 15%）。注意这**不等于饱和** —— 增益仍然显著（95% CI [+0.108, +0.236]），只是"还在涨，但涨得慢了"。

形式上也一致：局部幂律指数 α（= log₂(mean₂N / mean_N)）从 2.89 单调降到 **0.33**，远低于线性（α = 1），说明曲线已被 1.0 的天花板明显压缩。如果换算到 **logit 空间**（避开天花板），每个 doubling 的增量同样在下滑：**+3.05 → +2.30 → +1.48 → +1.35** —— 这正是 §4.2 里 logistic 模型高估 N=400 的根本原因（logistic 假定对数几率增量恒定，实测却在收缩）。

## 4. 讨论

### 4.1 是否饱和？

**没有，但 v2 的 N=400 实测把答案从"还没到平台"精确成了"刚过拐点"。**

- **判据一（最强，实测直接给出）**：N=200 → N=400 增益 **+0.172**，95% CI **[+0.108, +0.236]** 不含 0 → **N=400 仍未饱和**。这是直接证据，不再是推理。
- **判据二（绝对增益开始下滑）**：每翻倍增益 +0.287 → +0.250 → **+0.172**，第一次出现回落（衰减比 **0.688**）。此前 v1 依据 N≥50 的 13 个 run 拟合出的 `success ~ log₂N` 斜率 **+0.268 / 翻倍**（R² = 0.998）之所以会高估，正因为那段"恒定斜率"只在一个倍频程上成立。加入 N=400 后，用全部 5 档重拟合的斜率降到 **+0.222 / 翻倍**（R² = 0.970）。
- **判据三（相对）**：相对增益 +640% → +232% → +61% → **+26%**；局部 α 从 2.89 掉到 **0.33**。天花板压缩已经很明确。
- **判据四（独立于成功率的第二条曲线）**：val_loss 在 N=400 仍按幂律下降（0.0357 → 0.0182，−49%），且 5 点重拟合 R² = 0.9957，**没有任何平台迹象**。由于 val_loss 不受 1.0 上限压缩，这条证据权重很高。
- **判据五（脚本的「CI 不含 0」）**：**这个判据本身很弱**，在这种样本量下它几乎必然说"有差异"。不要拿它单独当饱和判据 —— 必须与判据二/三（收益是否在衰减）合起来看。**v2 的实际结论正是两者合看的结果：仍在显著上升（判据一），但已在减速（判据二/三）。**

> **一句话总结**：曲线现在处在"**还在涨，但每翻倍的涨幅已经明显变小**"的阶段。用最后一段的衰减比 0.688 递推，N=800 大约落在 **0.95 左右**（0.95–0.98 区间），但这是**未实测的外推**（见 §5.1）。

### 4.2 N=400：当初的外推 vs 实测（给模型打分）

v1 在只有四个点时给了五个模型的 N=400 预测。现在有了实测值 **0.832**，可以当场打分：

| 模型（均在 N=25…200 上拟合） | v1 预测 | 实测 | 偏差 | 评语 |
|---|---|---|---|---|
| Weibull `1−exp(−(N/N₀)^c)`，上限 1.0 | 0.953 | 0.832 | **+0.121** | 最差，天花板假定过于激进 |
| log-linear（N≥50 三点，斜率恒定） | 0.934 | 0.832 | **+0.102** | 只用一个倍频程外推，必然乐观 |
| **logistic（logit(success) ~ ln N，R² = 0.978）** | **0.926** | 0.832 | **+0.094** | **v1 推荐的模型，结果偏差第三** |
| 按增益比例衰减（0.287→0.250，比值 0.871） | 0.878 | 0.832 | +0.046 | **最接近的实用估计** |
| 按剩余空间比例衰减 | 0.745 | 0.832 | −0.087 | 唯一下偏的，但幅度同样大 |
| （对照）log-linear 用全部 4 点 | 0.857 | 0.832 | +0.025 | 保留低 N 锚点后反而不差 |

**三条值得记住的教训：**

1. **带固定上限（1.0）的参数模型会系统性高估**。它们在 logit/对数空间里假定每翻倍增量恒定，而实测的对数几率增量是收缩的（+3.05 → +2.30 → +1.48 → **+1.35**）。越是拟合优度高（R² 0.978 / 0.998）的模型，越容易让人对**(看不见的曲率)**过度自信。
2. **拟合优度 ≠ 外推能力**。logistic 的 R² 最高却排第三；用全部 4 点（含低 N 锚点）的朴素 log-linear 反而最好。**用 N 个点拟合 k 个参数再外推一个倍频程，本身就不该给太高的置信度。**
3. **val_loss 那条幂律反而略偏保守**：v1 由四点拟合外推得 N=400 的 val_loss ≈ **0.0213**，实测 **0.018153**，**高估 17.3%**（即真实改善比幂律预测的还要好一点）。加入实测点后重新拟合，指数从 −0.782 变为 **−0.828**（略变陡）。同样是 log-log 线性外推，loss 侧因为没有天花板压缩，误差方向与成功率侧相反。

**对后续实验的实际建议**：如果需要估计更大 N 的性能，**优先用"最近一段增益按观测到的衰减比递推"这种锚定在经验上的方法**，而不是拟合带上限的参数曲线；并且一定要把估计写成区间 + 明确标注"未实测"。

### 4.3 为什么对照组要冻结 N_B = 100

按 final-plan §6.5：UNet@100 均值 = 0.410 ≥ 0.10 → 轨道 B 沿用 N_B = 100。**N=400 实测之后这一点依然不变**：对照组冻结的目的是让 backbone 比较在固定数据量下进行，中途改 N_B 会让队友整条基线失效；而且 N=400 已经是本池上限（演示总共只有 400 条），不可持续。交付包见同目录 `handoff_lusen_n100.md`。

## 5. 局限性与效度威胁

### 5.1 N=400 已实测，N=800 未实测

v1 曾因 6000 GPU-min 配额吃紧而把 N=400 列为未实测。v2 之前上游优化了 dataloader（`data.preload`，吞吐 2.34×），单 run 训练从 4.5 h 降到 2.2 h，配额因此腾出余量，**N=400 × 5 seeds 已完整跑完并评测**（训练 job 135850，评测 job 136095，训练耗约 665 GPU-min）。所以「N=400 是否比 N=200 好」这个问题现在是**直接回答**（是，+0.172，CI 不含 0），不再是推理。

剩下的局限必须如实写明：

> 本文实测到 N=400（**本演示池的上限**，再往上需要重新生成演示数据）。N=800 及更高档位未实测；§4.1 末尾给出的 N≈800 → 0.95 是**按观测到的衰减比递推的外推**，仅用于说明趋势方向，不作为性能承诺。另外要证明真正的"饱和平台"，通常需要再往上至少一个数量级，**单个新点位本身并不能证明饱和**。

另有两项**尚未执行的诊断**（不影响主结论，但能进一步加固）：

### 5.2 单任务、单 backbone

全部结论只在 StackCube-v1 + RGB-UNet 上成立。α 的数值高度依赖任务本身的难度与观测模态（换成 state-based 或更好的 encoder，这条曲线的位置会整体平移）。不要外推到别的任务。

### 5.3 「数据量」与「梯度步数」的混淆 —— **已排除**

**威胁的本来面目**：若训练是固定 **epoch** 数，则 N 翻倍时梯度更新次数也翻倍，观察到的提升会同时混进「见到的独立样本更多」与「优化更充分」两件事，本文就只能在「固定 epoch 预算」这个弱化前提下谈 scaling。

**已排除**（逐 run 核对 `run.json`，**五档**一致，含 N=400）：

| 字段 | N=25 | N=50 | N=100 | N=200 | N=400 |
|---|---|---|---|---|---|
| `config.train.total_iters` | 100000 | 100000 | 100000 | 100000 | **100000** |
| `config.data.num_demos` | 25 | 50 | 100 | 200 | **400** |
| `config.data.val_num_demos` | 50 | 50 | 50 | 50 | **50** |
| `config.train.warmup_steps` | 500 | 500 | 500 | 500 | **500** |
| 中间 checkpoint 步数 | 10k/30k/60k | 10k/30k/60k | 10k/30k/60k | 10k/30k/60k | **10k/30k/60k** |

五档消耗的是**完全相同的 100000 次优化迭代**，唯一被改变的变量就是 `num_demos`。因此本文的性能差异可以**直接归因于演示数据本身**，无需在标题或结论里加「固定 epoch 预算」的限定。这同时也解释了 §2.4 的现象：既然总迭代数固定，训练墙钟自然几乎不随 N 变化。

**由此派生的一条反向注意点**：固定迭代数意味着 N=25 那档对同样的 25 条演示**重复采样次数是 N=200 的 8 倍**，理论上更容易过拟合。这并不削弱「数据越多越好」的主结论（test 种子从未参与训练，过拟合只会压低 N=25 的表现，而我们观察到的正是 N=25 极差），但它让 §5.4 的过拟合诊断更有必要 —— 值得补跑以说明小 N 的失败是「欠拟合/数据不足」还是「记忆了少数轨迹」。

### 5.4 「记忆」与「泛化」 —— 已由 loss 部分回答，行为层面仍可补强

**已回答的部分（强）**：§3.5 的 train loss 显示，各 N 的模型都把训练演示拟合到近乎无损（1e-4 ~ 1e-3），而 held-out 演示上的 val_loss 却从 **0.188 单调降到 0.018**（含 N=400，降幅 10.2×），且成功率同步从 1.7% 升到 83.2%。这条组合证据已经能排除掉最危险的竞争解释 ——

- ❌「N 小的模型差是因为没训够」→ 不成立，它们同样把训练数据背到 loss≈0；
- ✅ 真实机制是：**拟合能力在所有 N 上都过剩，瓶颈在泛化；演示数据越多，泛化越好。**

换句话说，本文观测到的是**泛化的 scaling，而不是拟合的 scaling**。这比单纯报告一条成功率曲线结实得多，建议在正文里占一整段。

**仍可补强的部分（行为层面）**：loss 是在单步动作预测上算的，而 `success_once` 是闭环执行的长程指标，两者不完全等价。若想把「记忆 vs 泛化」在**行为层面**也坐实，可以用 toml 里准备好的诊断：

```bash
# --split train，25 个回合，用所有 N 档共有的那 25 个演示种子
sbatch --partition=batch \
  --export=ALL,TASK=stackcube,EXPERIMENT=configs/experiments/data_size.toml,RUN_ROOT=$RUN_ROOT,SPLIT=train \
  slurm/eval_dual_gpu.sbatch
```

若 train 成功率远高于 test（N=400 时尤其值得看，因为它把整个演示池都用上了），说明存在过拟合；若两者接近同步上升，则提升是真正的泛化。**这个诊断很便宜（25 回合 vs 100 回合），如果配额还有余量，强烈建议补上** —— 它能直接回应审稿人"是不是只是记住了 400 条轨迹"的质疑。

> ✅ 已确认（`slurm/eval_dual_gpu.sbatch` 里 `SPLIT=${SPLIT:-test}`，直接 `--export=ALL,...,SPLIT=train` 即可；N=400 对应 `EXPERIMENT=configs/experiments/data_size_optional400.toml`）。

### 5.5 评测统计精度

单 run 100 回合的 Wilson 半宽约 ±0.08–0.10，因此**所有单点数字都应带区间**。另外 `success_once` 是比 `success_at_end` 宽松的指标（只要中途成功过就算），如果对照组用的是 `success_at_end`，两边数字不可直接比 —— 交付给队友时已把这一点写死在 `handoff_lusen_n100.md` 里。

### 5.6 N=25/50 只有 3 个种子

小 N 档种子数少，SD 估计本身不稳（N=25 只有 3 点，SD=0.012 可能偏乐观）。不过 §3.5 给出的 val_loss 在这两档的 CV 只有 1.1% / 2.3%，从 loss 侧看 3 个种子已经足够锁定位置；加上该档的结论在定性上非常明确（"几乎学不出来"，1.7%），不影响主结论。

## 6. 结论

1. StackCube-v1 上 Diffusion Policy 的成功率随演示数据量单调上升：**1.7% → 12.3% → 41.0% → 66.0% → 83.2%**（N=25…400，共 21 run），每档提升均统计显著（95% CI 都不含 0）。由于五档共享同一份优化步数预算（100000 iters）且数据为嵌套子集，**该提升可直接归因于演示数据本身**。
2. **N=400 已实测 = 0.832 ± 0.019**，比 N=200 高 **+0.172**（95% CI [+0.108, +0.236]）→ **尚未饱和**。但每翻倍的绝对增益**首次回落**（+0.287 → +0.250 → +0.172），局部 α 从 2.89 降到 **0.33**，对数几率增量也在收缩（+1.35 / 翻倍）→ **曲线已越过 log-linear 段，进入天花板压缩区**。
3. **外推必须谨慎（本文最实在的一条教训）**：v1 用 4 个点拟合的四个模型**全部高估** N=400（偏差 +0.046 ~ +0.121），其中拟合优度最高的 logistic（R² = 0.978）偏了 +0.094。原因是带固定上限的模型隐含"每翻倍增量恒定"，而实测是收缩的。要做外推，**优先用锚定在最近一段实测增益上的衰减递推**，并明确标注"未实测"。
4. 独立的 val_loss 曲线给出**不带天花板压缩**的佐证：加入 N=400 后仍服从幂律（`∝ N^(−0.828)`，R² = 0.9957），**没有平台迹象**；且它是比成功率更高信噪比的指标（种子间 CV 1–2.4%，N=400 为 5.8%，而 success_once 为 2.3–69%）。
5. **该效应是泛化的 scaling，不是拟合的 scaling**：所有 N 的 train loss 都压到近零（1e-4 ~ 1e-3），差异只体现在 held-out 上（val_loss 0.186 → 0.018）。小 N 的失败不是"没训够"。
6. 单位数据效率在 50 → 100 段最高，提示存在"冷启动门槛"；到 200 → 400 段每 +100 条演示只换回 **+0.086**。
7. 训练算力对 N 几乎不敏感（N≤200 四档 4.48 → 4.64 h），本任务的实际瓶颈是**演示数据获取成本**；而 **N=400 已是本演示池上限**，再要提升必须重新生成数据。
8. 按 final-plan §6.5，**N_B = 100（0.410 ± 0.029）冻结**为轨道 B 的 B0 参照并已交付；N=400 的实测评测结果不改变这一冻结决定。
